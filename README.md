# sqf-llm-fix-eval

бенчмарк LLM-моделей на исправление SQF-багов (Arma 3). этап 1 — статика, игровой этап ручной.

## что внутри
- tasks/2-1-killreward: задача (task.json), исходник с багами (source.sqf), игровой тест (test_killreward.sqf)
- examples/: примеры ответов моделей (формат `модель__номер.sqf`)
- variants/: ответы моделей, имя файла `модель__номер.sqf` (создаётся при запуске)
- analyze.py: разбирает variants/ и пишет results.xlsx
- runner.py: гонит промпт через openrouter и складывает ответы в variants/ (не проверялся без доступа к сети)
- suspicious.json: шаблоны подозрительных конструкций (дополняй по мере находок)

## как добавить прогон
1. вручную: положи ответ модели в variants/ как `имя__номер.sqf`, полный файл, не фрагмент
2. автоматом: впиши модели в models.txt, `set OPENROUTER_API_KEY=...`, `python runner.py --runs 3`
3. `python analyze.py`: обновит results.xlsx. ячейки "итог test_killreward" и "заметка" (желтые) не затираются

## как вписать итог игры
запусти test_killreward.sqf в arma 3 на версии модели (подмени fn_addKillReward.sqf), впиши число ошибок в желтую колонку

## что анализатор делает и чего нет
- ловушки 1-5 определяются по тексту (регулярки и разбор скобок). это эвристика: тимкилл ищется по `side group`, техника по `_instigator` или `effectivecommander`, массив вокруг format у hint помечается как "условно"
- лишние правки: число охранных `exitwith` до первого addEventHandler
- подозрительное: только шаблоны из suspicious.json. линтер (hemtt, sqf-vm) не подключен, существование команд автоматически не проверяется
- чего нет: запуска arma, проверки локальности в мп, этапа с документацией, hold-out задач. одна категория, одна задача
- оценки по чтению кода не заменяют игровой тест: верь желтой колонке, а не анализатору

## следующие шаги
- подключить hemtt (`hemtt lint`) или sqf-vm и писать их вывод в колонку "подозрительное"
- добавить задачи по категориям (локальность, extdb3, cba/ace, ui, ии)
- сверить по bi wiki: форму `setDamage [урон, эффекты, killer, instigator]`, порядок параметров MPKilled

## mcp-сервер (рекомендуемый способ)
сервер mcp_server.py хранит ловушки, проверки и таблицу у себя, агент видит только три инструмента: get_task, submit_answer, get_results.
1. `pip install -r requirements.txt` (нужен python 3.10+; версия mcp ограничена до 1.x, в 2.x переименован FastMCP)
2. положи папку бенчмарка вне рабочей папки проекта (например C:\tools\sqf-llm-fix-eval), иначе агент сможет прочитать analyze.py
3. подключи к агенту:
   - claude code: `claude mcp add sqf-llm-fix-eval -- python C:\tools\sqf-llm-fix-eval\mcp_server.py`
   - другие клиенты (json): `{"mcpServers": {"sqf-llm-fix-eval": {"command": "python", "args": ["C:/tools/sqf-llm-fix-eval/mcp_server.py"]}}}`
4. скопируй SKILL.md в скиллы агента (в claude code: папка со скиллом, в других агентах: в файл инструкций)
5. в чате напиши: "проверь модель на работу с арма3"

защита: талон одноразовый, оценка агенту не возвращается. не защищает от того, что агент прочитает файлы сервера с диска (поэтому п. 2) и от запуска всех прогонов в одном контексте. SKILL_cli.md это запасной вариант без mcp.
